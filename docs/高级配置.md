## 1. 配置分别存在哪里

不要把所有选项都写进 `config.json`。当前文件配置只负责数据库与 Skill 根目录，绝大多数界面设置保存在 PostgreSQL。

| 位置 | 管理内容 | 修改后如何生效 |
| --- | --- | --- |
| `config.json` | `database`、`skill_dir` | 启动时读取；修改后重启 |
| 进程环境变量 | 数据库、启动模型、配置文件/技能路径等 | 改环境并重启进程；Compose 改 `.env` 后重新创建应用容器 |
| 命令行参数 | 网页监听地址、数据目录、录制代理监听地址 | 重启时使用新参数 |
| LLM 页面 | 模型配置、全局激活项、轮询、重试 | 保存/激活后应用；已在进行的请求不等于被重新发送 |
| Agent / MCP / Skill / 工具页面 | 角色、提示词、能力及绑定 | 按页面保存；用下一次运行验证实际工具集 |
| 系统配置及其他管理页 | 捕获、代理、搜索、并发、通知等 | 多数运行时生效；并发 Worker 数用于之后启动的任务 |
| 当前浏览器 | 发送键位等前端偏好 | 即时生效，只保存在该浏览器 |

### 1.1 文件配置示例

下面是**本机已有 PostgreSQL**时可用的结构示例。填写实际密码、端口和数据库名；这不会自动安装 PostgreSQL 服务。

```json
{
  "database": {
    "host": "127.0.0.1",
    "port": 5432,
    "user": "artex",
    "password": "替换为数据库密码",
    "dbname": "artex",
    "sslmode": "disable"
  },
  "skill_dir": "./skills"
}
```

本机回环或受控容器网络可按实际情况使用 `disable`；连接需要 TLS 的数据库，应采用数据库服务要求的 SSL 配置。也可把 `database` 换成只有 `dsn` 的对象，**非空 `database.dsn` 优先于分字段**。

几个容易误判的地方：

- 数据库连接优先级：`ARTEX_PG_DSN` → `config.json` 中的 `database.dsn` → `database` 分字段。改文件无效时先检查环境变量。
- 配置文件位置：`ARTEX_CONFIG` 指定路径 → 当前工作目录的 `config.json` → 可执行文件旁的 `config.json`。
- Skill 路径优先级：`ARTEX_SKILL_DIR` → `skill_dir` → 可执行文件旁的 `skills/`。
- 相对 `skill_dir` 按进程当前工作目录解析。服务管理器中建议使用绝对路径。
- 仓库 `config.example.json` 的端口是 **5433**，Skill 示例路径是 **`/opt/artex/skills`**。复制后必须改成自己的值，不能只改密码。
- JSON 不能写注释或尾逗号。配置文件格式错误可能最终表现为“未找到数据库配置”。

### 1.2 常用环境变量

| 变量 | 用途 / 可填内容 |
| --- | --- |
| `ARTEX_CONFIG` | 明确指定配置文件路径 |
| `ARTEX_PG_DSN` | PostgreSQL 完整连接串，覆盖文件里的数据库配置 |
| `ARTEX_SKILL_DIR` | Skill 根目录 |
| `ANTHROPIC_API_KEY` | Anthropic 协议启动模型的凭据 |
| `OPENAI_API_KEY` | OpenAI Chat Completions / Responses 协议启动模型的凭据 |
| `ARTEX_LLM_PROVIDER` | `anthropic`、`openai` 或 `openai-responses` |
| `ARTEX_LLM_MODEL` | 服务商实际模型 ID，建议明确填写 |
| `ARTEX_LLM_BASE_URL` | API 基础地址 |
| `ARTEX_LLM_PROXY` | 模型请求代理，支持 `http`、`https`、`socks5` |
| `ARTEX_LLM_STREAM` | 启动模型是否流式；`false`、`0`、`off`、`no` 可关闭，默认开启 |
| `ARTEX_IMAGE` / `ARTEX_TAG` | Compose 选择镜像和标签，供 Compose 使用，不是应用内部配置 |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | Compose 数据库容器及连接信息 |

**数据库中已有激活模型时，启动优先使用它，环境模型只作没有该配置时的来源。** 同时填两种 Key 却没指定 Provider 时，环境配置优先选择 Anthropic。初次使用推荐直接在 LLM 页面配置，减少来源混淆。

`.env` 是 Compose 使用的文件，直接启动 `artex` 不会自动读取它；也不是把任意变量写进去就会传进容器。默认 Compose 只转发其 `environment` 中声明的变量，例如 `ARTEX_LLM_STREAM` 需要另外显式传入容器，或直接在 UI 修改模型的流式选项。

前端开发变量单独见[部署维护与排错](部署维护与排错.md#source)：`NEXT_PUBLIC_MOCK` 只控制模拟界面，`NEXT_EXPORT` 控制静态导出，`AUTOPENTEST_API` 设置开发反代后端。不要把后端数据库密码放进 `NEXT_PUBLIC_*` 变量。

### 1.3 启动参数

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `-addr` | `:8787` | 网页和 API 监听地址；冒号前留空表示不只绑定回环地址 |
| `-data` | 可执行文件旁的 `data/` | 工作文件、流量、归档等文件存储根目录 |
| `-proxy` | `127.0.0.1:8788` | 流量录制代理监听地址；空字符串禁用代理服务 |

例如本地二进制：

```bash
./start.sh -addr 127.0.0.1:8787 -proxy 127.0.0.1:8788
```

Windows：

```powershell
.\start.bat -addr 127.0.0.1:8787 -proxy 127.0.0.1:8788
```

Docker 镜像的启动参数把代理监听改为容器内 `:8788`，宿主机仍仅映射到 `127.0.0.1:8788`。**`-proxy` 是本地录制服务的监听位置，不是外部出口代理 URL。**

## 2. 模型选择与故障转移

### 2.1 格式和地址如何选择

| 格式 | 对应服务协议 | 常见误区 |
| --- | --- | --- |
| Anthropic | Messages 类接口 | 模型名字带 Claude，并不代表网关一定使用此协议 |
| OpenAI (Chat Completions) | Chat Completions 类接口 | 同一个网关不一定同时支持 Responses |
| OpenAI (Responses API) | Responses 类接口 | 切换格式后，要重新验证模型、地址和参数 |

以服务商提供的接口协议为准。Base URL 使用它明确给出的基础地址；模型填实际可调用的 ID。更换 API Key 后先测试，再保存并确认激活状态。编辑已有配置时 Key 留空表示保留，界面只显示提示值，不能从那里取回原 Key。

### 2.2 谁决定某个角色用哪个模型

**优先级：Agent 绑定 → 任务 LLM 配置链 / 独立会话指定 → 全局激活配置。**

例如，全局激活 A，任务选择 B，但 Worker 的「默认模型」绑定 C，那么这个 Worker 使用 C。要让它跟随任务，把 Agent 绑定改为跟随并保存。

角色绑定无法解析或构建时可能降级到任务链/全局，因此遇到异常仍应看会话和系统审计中实际使用的配置，不能只根据某个下拉框推断。运行中调用不会因为你修改配置而自动安全重放。

### 2.3 任务配置链和全局轮询的区别

| 项目 | 任务 LLM 配置链 | LLM 页面全局轮询 |
| --- | --- | --- |
| 设置入口 | 新建任务，或任务顶部模型控制 | LLM 页的轮询设置 |
| 顺序 | 按列表顺序；可上下移动，详情中可切换当前项 | 激活配置恒为第一，其余按优先级，同优先级可轮换 |
| 自动切换条件 | 明确余额、额度等耗尽信号；普通 429 限速或网络超时不等于额度耗尽 | 按失败、重试与熔断策略使用可用备选 |
| 影响范围 | 当前任务中实际走该链的角色 | 默认影响走全局激活路径的调用 |
| 专用 Agent 绑定 | 优先于任务链 | 默认不偷偷改用其他配置；需另开「指定模型失败时也兜底」才允许该类回退 |
| 没有可用项 | 显示额度链耗尽，等待修复或切换 | 取决于备选可用性与冷却状态 |

全局轮询默认关闭，至少需要 2 个填有 Key 且参与轮询的配置才有实际备选。某个配置不希望参与兜底，可打开「不参与轮询」。

任务链耗尽后的处理：

1. 到 LLM 页确认备用配置本身可用。
2. 打开任务顶部的 LLM 配置链，补充配置或切换当前配置并保存。
3. 查看系统审计和额度阻塞的工作是否恢复。
4. 原任务若手动暂停，仍需你恢复；已结束任务不会只因换模型自动重新扫描。

### 2.4 模型高级字段

| 字段 | 含义和建议 |
| --- | --- |
| 每秒 / 每分钟限速 | `0` 表示不限；同一配置由多个 Agent 共享限速，实际 HTTP 尝试包含重试 |
| 上下文窗口（K） | 单位为千 Token；`0` 使用 200K 默认值，界面上限 1000K。按模型真实上限填，不要把低容量模型人为填大 |
| 单次输出上限 | `0` 不发送该字段，由接口决定；不是任务总 Token 预算 |
| 上限字段名 | Chat Completions 根据网关支持选择 `max_tokens` 或 `max_completion_tokens`，不要只靠模型名字猜测 |
| 流式输出 | 默认开启；关闭后仍会调用模型，只是通常等完整响应返回，不等于任务卡死 |
| 思考开关 / 思考强度 | 只填服务商支持的值；不兼容会导致 400 等错误，默认不发送通常更容易接通 |
| 代理 | 只影响模型请求，不自动改变目标访问或搜索出口 |
| 自定义会话头 | 按网关要求发送会话标识；没有明确要求就留空 |
| 重试覆盖 | 仅覆盖该模型的前三层重试；其他配置仍用自己的覆盖或全局值 |

## 3. 预算、并发和重试

### 3.1 四种限制不是一回事

| 限制 | 管什么 | `0` / 留空的含义 |
| --- | --- | --- |
| 任务超时（分钟） | 整个任务运行的时间边界 | 不限时，到点会做收尾而非瞬间杀死 |
| Agent 运行时长（秒） | 一次 Agent 运行 | `0` 不限 |
| Agent 最大循环次数 | 一次运行的模型/工具交互轮次 | `0` 不限 |
| 模型单次输出上限 | 一条回复最多生成多少 Token | `0` 不发送限制字段 |

Agent 到预算后还可能进入收尾轮次，把已确认内容写回。因此这些不是严格的费用封顶功能。想降低成本，优先缩小任务目标、减少并发、关闭不需要的联网搜索和自动证据绑定，并观察实际 Token 用量。

### 3.2 重试与退避

入口：「LLM → 重试与退避」。界面当前有五层：

| 层 | 处理什么 | 当前内置次数 / 策略 |
| --- | --- | --- |
| 建连重试 | 200 响应前的连接问题及 408 / 429 / 部分 5xx | 3 次，指数退避 |
| 空响应重试 | OpenAI 格式正常结束但完全无内容 | 2 次；因输出上限截断的无内容不按此处理 |
| 同 provider 安全窗口重试 | 流建立后出错，但尚未向调用方交付输出 | 2 次；已交付输出后不按同一请求直接重放 |
| 轮询熔断 | 持续失败的配置暂时冷却 | 瞬时失败默认累计 3 次；确定性错误可立即熔断；冷却按 1 / 5 / 30 分钟递增 |
| 意图重跑 | Worker 的外层模型错误恢复 | 默认 2 次，固定 3 秒间隔；不是只重发一个 HTTP 包 |

填写规则：

- 次数留空或 `0`：使用默认，不表示关闭。
- 次数 `-1`：关闭对应重试；熔断层表示不因瞬时错误熔断，确定性错误仍可熔断。
- 间隔留空或 `0`：使用默认退避；填写正数则使用固定毫秒数。
- 前三层可以在模型配置中单独覆盖；后两层在全局设置。
- 保存后新调用使用新策略，正在运行的那轮仍可能使用旧参数。

不要把每一层都设成很大。外层意图重跑会再次经历内层重试，总请求量可能相乘。401 / 403、错误模型名、错误接口地址需要修配置；反复重试不能修复它们。

## 4. 流量、代理和网络搜索

### 4.1 分清三种代理

| 设置 | 影响范围 | 在哪里改 |
| --- | --- | --- |
| 全局代理 | Agent 的目标流量出口，以及项目更新链路使用的代理 | 系统配置 |
| LLM 代理 | 对模型服务的请求 | 每份 LLM 配置，或启动环境变量 |
| 网络搜索代理 | 相应搜索后端的请求 | 系统配置的网络搜索卡片 |

三者互相独立，填一个不会自动替另外两个填值。支持的常见写法为 `http://主机:端口`、`https://主机:端口`、`socks5://主机:端口`；需要认证时按代理实际要求填写。

开流量捕获时：目标请求先经过录制代理，再经全局代理出去。关捕获时：代理配置直接交给 Bash / WebFetch 等使用。部分命令行工具不支持或忽略 `ALL_PROXY`，尤其 SOCKS 场景，不能因此承诺所有工具通信都会走代理。

容器里填写 `127.0.0.1:1080` 指向容器自己。代理在宿主机时，需要使用容器可达的地址。先在同一执行环境验证连接，再改应用设置。

### 4.2 捕获与证据自动绑定

| 选项 | 默认 | 生效和边界 |
| --- | --- | --- |
| 流量捕获 | 关 | 切换会重建 Agent 的代理/工具配置；不补录过去请求，也不等于抓取所有网络协议 |
| Agent 自动绑定流量 | 关 | 后续 Agent 轮次采用；关闭后拒绝新的自动绑定；人工绑定、已有证据和捕获开关独立 |

需要 HTTP 证据时应在任务前启用捕获，确认代理启动正常。HTTPS 录制依赖录制 CA；优先使用系统为 Agent 提供的代理与证书配置。自定义客户端需要单独信任对应 CA，不建议用永久关闭 TLS 校验来掩盖证书问题。

记录 HTTP 流量不等于记录 LLM 请求。后者在「LLM 录制」单独开启。

### 4.3 网络搜索

启用步骤：先在「系统配置 → 网络搜索」打开总开关、选择来源并配置凭据，再到需要使用它的 Agent 中开启网络搜索。

| 来源 | 配置要求 |
| --- | --- |
| DuckDuckGo（ddgs） | 不需要 API Key；仍受执行环境网络与依赖可用性影响 |
| Brave（免费版） | 填 Brave API Key |
| Tavily | 填 Tavily API Key |
| DeepSeek（官方） | 按当前项目实现，复用全局激活的 DeepSeek 官方配置，并要求 Anthropic 协议 |

保存后使用卡片的搜索测试确认。普通搜索返回标题、链接、摘要，正文读取由 WebFetch 等处理；搜索不经过录制代理。

DeepSeek 来源由服务端搜索，返回标题和链接，可能额外产生模型 Token 用量；切换全局激活模型后，该来源可能不再可用。它不等于“任何 OpenAI 兼容网关都支持搜索”。

## 5. Agent 的配置与提示词

在「Agent」中打开角色详情，可以管理默认模型、预算、提示词、MCP、Skill 和 Tools 等。初期保留内置分工，只改模型和必要预算。

常用角色包括目标解析、Planner、Worker、主 Agent，以及用于报告和复测的角色。角色名称和是否启用以当前列表为准；如果人为停用或删除报告相关 Agent，发现入库后不一定还有报告生成流程。

### 5.1 修改提示词的可靠步骤

1. 打开正确角色，先阅读现有提示词和可插入变量。
2. 记录当前版本，只围绕要解决的问题修改。
3. 使用「渲染预览」确认占位变量正常替换；预览使用示例值，不是实际执行结果。
4. 分别保存配置与提示词，注意不同区域的保存按钮。
5. 用一个小型本地任务观察下一次运行。
6. 效果不对时查看版本历史、对比或恢复默认。

不要删掉写回事实、上报证据、遵守范围和收尾所需的约定。把提示词变短不一定更省费用；如果因此反复重试或漏交结果，总费用可能增加。

### 5.2 收尾与实验性压缩

收尾提示词用于在单次运行到预算时保存已确认的工作；任务超时收尾则处理整个任务到期，两者语义不同。收尾轮数 `0` 使用内置默认。调整后按下一次运行验证，不能把收尾预算设得过小又期待所有记录一定保存。

「系统配置 → noa 上下文压缩」是实验功能，默认关闭。开启会改变上下文压缩方式并归档原文到任务工作目录，对之后启动的运行生效。长任务有上下文问题时，先确认模型窗口填写正确，再评估是否启用。

### 5.3 自定义 Agent 的触发

自定义 Agent 的「触发」页可配置定时、发现入库、目标达成、任务超时、工具调用完成、任务创建等事件。每次触发会创建运行会话，可在「对话」中查看。

还可选择串行 / 并行，以及排队触发是否按任务或全部合并。高频工具事件叠加并行触发容易产生很多会话；先只启用一个明确事件，设置合适并发并检查结果。这里的定时触发与「计划任务」的任务运行时间窗口不是同一功能。

## 6. MCP、Skill 和自定义工具

选择原则：已有工具够用就直接使用；需要外部服务时接 MCP；需要一套操作说明和脚本时使用 Skill；确实缺少一个小执行入口时再建自定义工具。

### 6.1 MCP：连接外部工具服务器

1. 打开「MCP」，添加服务器并命名。
2. 选择传输方式，填写对应配置。
3. 保存并启用服务器，在工具列表点击「刷新」。
4. 确认发现了预期工具，再为需要使用它的 Agent 授权。
5. 在新的小任务或会话中确认 Agent 实际拿到工具。

| 传输 | 填什么 | 注意事项 |
| --- | --- | --- |
| `stdio` 本地 | 命令、空格分隔参数、环境变量 | 程序在 ARTEX 服务所在机器/容器运行，不是在你的浏览器电脑运行 |
| `http` 远程 | Streamable HTTP 端点、请求头 | 使用服务明确提供的 MCP URL |
| `sse` 旧版 | SSE 端点、请求头 | 通常为 `/sse`，消息地址由连接协商返回，不要把 `/message` 当入口 |

环境变量 / 远程请求头按**每行 `KEY=VALUE`**填写，例如 `Authorization=Bearer <实际令牌>`。stdio 的参数框当前按空白拆分，并不按 Shell 的引号规则解析；包含空格的单个参数需要特别核对，优先使用不含空格的路径。

发现工具成功但 Agent 不会用时，检查：服务是否启用、是否给该 Agent 授权、Agent 自身是否可运行、当前运行是否仍持有之前的工具集。Docker 宿主机安装了某程序，不代表容器内也有；内置镜像与自行下载的二进制工具环境也不完全相同。

### 6.2 Skill：说明和配套文件

「Skill」可创建技能、编辑 `SKILL.md` 和配套文件，设置按 Agent 的可见性，也可查看调用统计。一个基本目录形态是：

```text
skills/
  local-file-review/
    SKILL.md
    scripts/
    references/
```

在页面创建时，名称和描述必填，正文可先生成骨架再补充。描述写清“什么时候用”，正文写“输入、步骤、结果如何验收”。技能文件可见不代表依赖程序已安装，`compatibility` 说明也不会自动安装依赖。

Compose 把仓库的 `./skills` 挂到 `/app/skills`，覆盖镜像内置目录；修改挂载文件不需要重建镜像。升级前备份自定义 Skill，新版本内置技能与本地改动应逐项合并，避免整目录覆盖。

### 6.3 系统工具和自定义工具

「工具 → 系统工具」可编辑描述、部分参数默认值和 Agent 绑定。参数名、类型和必填属性只读。禁用或解绑关键写回工具，可能导致 Agent 做了工作却无法记录结果。

「工具 → 自定义工具」支持：

| 类型 | 用途 |
| --- | --- |
| `shell` | 声明 Bash 环境中存在的能力 |
| `command` | 按参数填充 Shell 命令模板 |
| `script` | 执行 Python 脚本，参数可通过 stdin JSON / `TOOL_X` 环境变量获得 |
| `http` | 按模板构造 HTTP 方法、URL、请求头和正文 |

**一个不访问网络的练习：**创建 `script` 类型工具 `text_length`，描述为“返回输入文本的字符数”。参数 Schema：

```json
{
  "type": "object",
  "properties": {
    "text": { "type": "string", "description": "需要计数的文本" }
  },
  "required": ["text"]
}
```

Python 正文：

```python
import json
import sys

params = json.load(sys.stdin)
print(len(params["text"]))
```

先到「系统配置 → 自定义脚本 · Python 解释器」检测或填写服务器上的解释器路径。在工具的「测试运行」输入 `{"text":"ARTEX"}`，预期输出 `5`，再保存并绑定目标 Agent。

测试运行使用当前表单且不会替你保存，**但会真实执行工具**。测试 HTTP 或命令工具时也会真实产生操作，应使用本地练习参数。不要把不受控输入直接拼成任意 Shell 命令。

## 7. 范围、拦截与审批

### 7.1 四种边界分别负责什么

| 机制 | 管理什么 | 不能误认为 |
| --- | --- | --- |
| 企业范围 / 测试资产 | 目标组织、范围上下文与覆盖记录 | 自动启动测试的指令或完整网络隔离 |
| 操作约束 | 告诉 Planner / Worker 哪些操作允许、哪些禁止 | 强制执行的操作系统沙箱 |
| 资产拦截 / 任务允许规则 | 对纳入资产判定路径的域名、IP、URL、CIDR 做限制 | 对任意外部程序所有网络流量的防火墙 |
| 工具拦截 / 模型审查 / 人工审批 | 对启用拦截的工具调用作允许、拒绝或等待决定 | 不勾选工具也会自动拦截所有操作 |

### 7.2 资产规则的判定顺序

「资产拦截」维护全局规则；新建任务和任务总览中可维护本任务规则。支持域名 / IP / URL 全等或模糊匹配，以及 CIDR。

顺序是：**先匹配全局和任务的拦截规则，命中就禁止；没命中时，如果任务有允许规则，则必须命中至少一条允许规则；没有允许规则就不启用白名单。**

因此，“允许”不能覆盖已命中的“拦截”。想只允许一个本地实验服务，优先选择适合目标的精确 IP / 域名 / URL 类型，并核对协议、端口和路径的匹配范围。模糊匹配不是自动支持任意通配符表达式；以界面类型说明为准。

项目默认包含政府、教育域名相关的模糊拦截规则。发现本地任务被拒绝时，先看具体命中的规则与输入，不要为解决单次报错批量关闭所有保护。

### 7.3 工具规则和模型兜底

进入「拦截规则」：

1. 先选择哪些工具进入拦截流程。页面提示“未启用任何工具”时，规则和模型兜底都不会生效。
2. 新建规则，填名称和优先级；**数字越大越先匹配，首条命中后不继续匹配后续规则**。
3. 匹配对象选工具名或工具输入 JSON；方式选字符串包含或正则。
4. 动作选允许、禁止或向用户申请；需要时填写拒绝消息、审批等待时间和超时动作。
5. 保存并启用，用一个小的本地操作验证命中结果。

例如希望所有 `Bash` 操作先人工核对，可以使用工具名正则 `^Bash$`，动作选「向用户申请」，并把对应工具加入拦截范围。先确认实际工具名，且没有更高优先级规则提前放行。

「模型配置」页签还可以调整模型审查提示词、使用的 LLM、超时、重试，以及解析不确定或模型失败后的策略。审查失败可选择放行、转人工或拦截；这是不同的运行取舍，不能把“模型失败时放行”理解成已经通过了审查。

模型审批失败额外重试可设 0–20 次，`0` 表示不重试；这与 LLM 通用重试页“0 使用默认”的语义不同。每次尝试有独立超时，内层模型重试也会增加总等待。

### 7.4 处理待审批操作

到全局「审批记录」、任务「拦截审批」或会话审批卡片展开详情，核对工具、参数、命中原因和上下文，再允许或拒绝。批准一条调用不代表关闭规则。审批超时按已配置动作处理；人离开页面时，任务可能仍在等待或被自动拒绝。

## 8. 通知推送

入口：「通知推送」。当前包含钉钉、飞书、企业微信、Telegram、邮件和自定义 Webhook 等渠道，具体字段以选择后的表单为准。

1. 在全局设置填**回链地址**，使用接收者实际能访问的 ARTEX 地址；它决定通知里的链接，不是监听地址。
2. 添加渠道，填写渠道名称和必需凭据。
3. 选择实时或汇总。实时按事件发送，汇总按全局周期合并；汇总周期不会影响实时渠道。
4. 根据需要设置最低级别、包含/排除的漏洞类型、限定任务 ID 和资产 ID。
5. 保存并启用；确认收件人后使用测试发送。
6. 在「投递记录」确认成功与失败；修复配置后可对允许重发的失败/跳过记录重发。

类型过滤中，**排除优先于包含**。限流留空使用渠道默认，`0` 表示不限；超限消息延后发送，不是立即丢弃。收到测试消息只能证明渠道测试成功，业务消息还要经过启用状态、事件条件和过滤器。

测试按钮会真实发消息。不要把 Webhook URL、机器人 Token 或邮件密码放进报告或截图；需要共享配置时只分享字段名称和脱敏值。

## 9. 访问验证和浏览器偏好

「系统配置 → HTTP Basic Auth」提供独立的一层访问验证。默认关闭；启用后先通过浏览器原生验证，再进入 ARTEX 登录。这里的用户名密码与 `ARTEX` 管理员账号不同。

填写用户名和密码，启用后点击「保存访问验证」。用户名不能包含冒号，密码至少 8 位、最多 72 字节；以后保存时密码留空表示保留。配置保存在数据库，保存立即生效；健康检查 `/api/health` 保持公开。

浏览器可能缓存凭据，验证启用效果可使用新的无痕窗口。Basic Auth 不能替代 HTTPS。忘记管理员密码和忘记这一层密码，处理方法也不同，见[故障排查](部署维护与排错.md#password)。

对话发送键位在系统配置中更改后即时生效，它属于浏览器偏好；其他电脑或浏览器需独立设置。
