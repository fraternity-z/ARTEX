## 1. 创建任务与复用模板

### 1.1 写好描述和目标

在「任务 → 新建任务」中，**描述和目标必填**。描述回答“对象是什么、已有资料是什么、边界在哪里”；目标回答“做成什么样就可以结束”。不要只写“全面测试一下”，否则很难判断何时完成，也不容易控制用量。

本地隔离实验任务可以按下面的结构填写。尖括号内容需要替换成实际信息：

```text
描述：
对象：<ARTEX 执行环境可访问的本地实验服务地址>。
背景：这是可重置的隔离练习环境，已有说明文件通过附件提供。
允许：只读取指定服务的公开页面，核对响应和说明文件。
禁止：访问其他主机、猜测密码、改写数据、安装新软件。
结束条件：完成指定页面检查；遇到需要额外权限的步骤先申请，不自行扩大范围。

目标：
记录指定页面的状态码与主要功能，列出有直接证据的观察结果。
每条结论注明证据来源；不能确认的事项单独列出。完成后结束任务。
```

描述里的约束会用于提取任务操作约束；创建后仍应到「总览 → 操作约束」核对。文字约束不等于网络防火墙，严格限制范围还需要[资产规则和工具审批](高级配置.md#intercept)。

### 1.2 新建表单每一项怎么用

| 字段 | 用途和建议 |
| --- | --- |
| 名称 | 可选，给自己看的简短名称；不替代描述和目标 |
| 任务分类 | 可选，单个分类，方便筛选；分类不会改变 Agent 的执行方式 |
| 任务模板 | 预填描述、目标、分类和任务级资产规则，应用后仍可修改 |
| 描述 / 目标 | 必填，明确对象、背景、边界与可验收的结果 |
| 上传文件 | 可多选；上传到服务器后，绝对路径追加到描述中，供 Agent 用 Read / Bash 读取 |
| 关联任务 | 最多 8 个来源任务；实时只读继承其持久化黑板、资产范围与相关流量，新任务写自己的记录 |
| 关联企业资产范围 | 将所选企业当前已有资产加入测试资产，并提供企业范围上下文；不会自动生成测试意图 |
| 任务级资产拦截 / 允许规则 | 只影响本任务；先看全局和任务拦截，再看任务允许列表 |
| LLM 配置链 | 有序模型列表，只在明确额度不足时自动推进下一项；留空跟随 Agent / 全局配置 |
| 计划启动 | 按指定日期或每周时间窗口启动和暂停；没选「创建后立即启动」就等待窗口 |

附件里只放本次工作必要的内容。上传并不会把一份资料自动转换成任务目标；仍要在描述中说明“读哪个文件、用来做什么”。模板应用可能替换已有描述，注意不要丢掉附件路径。

关联任务是**读取已有知识**，不是复制出一套可以任意修改的原任务数据。继承的发现或流量证据需要修改时，进入来源任务操作。它也不是“等来源任务结束后才运行”的依赖编排开关。

### 1.3 高级设置不用一次全开

| 参数 | 当前默认 | 什么时候改 |
| --- | --- | --- |
| 任务超时 | 留空 / 0 表示不限时 | 想为练习设置时间边界时填写分钟数；到点进入收尾，最终为 `timeout` |
| Planner 心跳 | 10 分钟，最小 10 分钟 | 没有事件触发时兜底唤醒规划；不是 HTTP 请求间隔 |
| 直接下发首个意图 | 关闭 | 对象和工作已经很明确时，可让 Worker 直接执行描述与目标，再交给 Planner |
| 资产覆盖度功能 | 开启 | 关闭后不计算或展示覆盖度，也不提供范围类工具；仍可关联企业 |

任务超时、Agent 每次运行预算和模型单次输出上限是不同限制。详细关系见[高级配置](高级配置.md#budgets)。

### 1.4 保存和使用模板

1. 在新建表单填好描述、目标、分类和资产规则。
2. 点击「另存为模板」，填写模板名称并保存。
3. 下次创建时，在「任务模板」中搜索选择，确认预填内容后再创建。
4. 需要统一调整模板时点击「管理模板」。

模板保存的是描述、目标、分类和任务级规则，**不保存整份运行配置**。模型链、关联任务、计划、超时等仍需在新任务里设置。应用模板后只是复制内容；之后修改或删除模板，不会改变已经创建的任务。

## 2. 理解运行状态和控制按钮

### 2.1 任务为什么还没开始

| 看到的情况 | 含义 / 检查方式 |
| --- | --- |
| 排队 | 达到任务并发上限，等其他任务让出位置；查看列表上的并发限制 |
| 等待计划窗口 | 已绑定计划，但当前不在允许执行时间；到「计划任务」看时区与下次窗口 |
| 已暂停 | 自动执行被暂停；确认原因后使用恢复 / 继续 |
| 正在规划或工作 | 查看会话里的 Planner / Workers，而不是只看列表是否有新漏洞 |
| 等待审批 | 打开任务「拦截审批」或全局「审批记录」处理 |
| 暂无活动 | 可能正在等模型响应、限速或重试；结合会话、LLM 录制和日志判断 |
| 配置链额度已耗尽 | 没有可继续使用的任务模型；添加可用配置或手动切换当前配置 |
| 已完成 / 已结束 | 普通恢复按钮不可用；查看结果，按需要复测或创建后续任务 |

列表与详情并非每个字段都逐毫秒更新；短暂显示旧状态时先等一次刷新，不要重复创建相同任务。

### 2.2 暂停、停止、删除分别影响什么

| 操作 | 影响范围 |
| --- | --- |
| 任务顶部「暂停」 / 列表「暂停任务」 | 暂停该任务的自动规划和 Worker 执行，也取消该任务主 Agent 当前这一轮对话；保存已有记录 |
| 任务「恢复」 / 列表「继续任务」 | 让暂停任务继续；可能重新排队，仍受计划窗口等条件约束 |
| 主 Agent 输入框旁「停止当前执行」 | 停止当前对话这一轮；不能用它代替暂停整个任务 |
| 会话中「暂停当前 Worker」 | 只控制该条工作；其他 Worker 和 Planner 仍可能运行 |
| 删除 Worker | 需要原因；软删除保留意图和产出，硬删除可能清理仅由它支撑的节点，应读清确认内容 |
| 归档任务 | 将可归档任务转入冷存储，之后可还原；不是普通暂停 |
| 删除任务 / 永久删除归档 | 删除相应记录或归档内容，不是可恢复的暂停按钮 |

暂停不会撤销已经完成的工具操作。恢复也不保证从某条 Shell 命令的中间一行继续；它恢复的是任务调度和后续工作。

### 2.3 控制用量的两个并发入口

- 「任务」页的**任务并发限制**控制同时运行多少个任务。默认关闭；开启但未另设上限时为 5。
- 「系统配置 → 并发工作 Agent 数」控制**每个任务**的 Worker 数量，默认 3，对之后启动的任务生效。

例如 2 个运行任务、每个 3 个 Worker，就可能有 6 个 Worker 同时工作，此外还有 Planner、主 Agent、报告等调用。这个乘积不是整个系统模型请求的绝对上限。先降低并发，再根据服务商限制设置模型限速。

## 3. 看懂任务详情

进入任务后，按下面的顺序看通常最有效：

| 页签 | 主要用途 |
| --- | --- |
| 会话 | 看主 Agent、规划 Planner、Workers、系统审计的实际执行过程，展开输入输出定位问题 |
| 总览 | 看目标、任务信息、操作约束和其他运行状态；核对范围是否符合原意 |
| 探索链路 | 看目标、意图、事实、提示和发现之间的来源关系 |
| 播报板 | 按事件观察已写入的知识和结果，适合了解当前进展 |
| 发现 | 查本任务及可见继承记录的漏洞结果 |
| 复测 | 选择本任务漏洞，发起并查看历次复测 |
| 测试资产 | 看本任务纳入范围的对象，可新增资产或移出当前任务 |
| 资产覆盖图 | 从资产关系看测试覆盖情况；关闭覆盖功能后不显示进度含义 |
| 拦截审批 | 处理本任务待审批操作，并查看历史详情 |
| 报告 | 查看当前汇总 Markdown，并复制内容 |

**覆盖了资产，不等于证明资产没有漏洞。** 覆盖图表示任务对资产的探索记录，不能替代结论审核。类似地，目标完成是任务自身的完成判定，不是对安全性的保证。

操作约束可在「总览」增删改，区分允许与禁止。默认会注入 Planner 和 Worker 的后续读取；如果全局关闭了其中某个角色的约束注入，该角色就看不到这些约束。调整后应核对实际执行，而不是只确认文字已经保存。

## 4. 通过对话补充信息

### 4.1 独立对话和任务主 Agent

「对话」页用于创建某个 Agent 的独立会话；任务「会话」里的主 Agent 则带有当前任务上下文。想解释当前任务的结果或交接新线索时，优先进入对应任务，避免只在独立对话中说“刚才那个任务”。

可以发送：

```text
请解释当前任务已有的三条事实分别依据什么证据，不执行新的工具操作。
```

或者提供明确的新信息：

```text
附件是本地练习环境的新说明，请先读取并核对。
本轮仍只允许分析文件；如果需要访问服务，先说明原因并等待审批。
```

支持 `@` 引用界面提供的漏洞、资产等对象；用选择器选择实际记录，比手打容易混淆的标题更可靠。也可上传附件，确认附件属于当前会话。

### 4.2 正在运行时想插一句问题

支持旁路提问的输入框可以输入 `/btw 问题`，例如：

```text
/btw 当前等待的是模型回复，还是需要我处理审批？
```

旁路问题用于围绕当前上下文询问进度或解释，不应当作修改任务目标的可靠入口。需要改变执行范围、暂停任务或补充约束时，使用任务控制和对应编辑入口。

默认 **Enter 发送，Shift+Enter 换行**。可在「系统配置」改为 **Ctrl+Enter 发送，Enter 换行**，后一种模式在 macOS 也接受 Cmd+Enter。这是当前浏览器保存的前端偏好，换浏览器不会自动同步。

## 5. 管理资产和同步来源

### 5.1 企业、全局资产、测试资产的关系

- **企业**用于归集资产和描述范围。
- **全局资产**是多个任务共享的资产库。
- **测试资产**是某个任务当前纳入的对象；从任务移出，不等于从全局资产库永久删除。

进入「资产 → 新增企业」，填写名称与资产范围。范围每行一条，编辑器会识别域名、IP、CIDR、ICP 备案和企业关键词，并提示错误行。

已有匹配资产可按范围归属企业。**企业关键词只作为 Agent 提示，不会自动认领资产；ICP 按精确匹配处理。** 保存前看识别结果，避免把一个范围写成一大行无法识别的描述。

创建任务时选「关联企业资产范围」，会加入企业**当前已有**资产，并提供范围上下文。它不意味着自动遍历所有资产，也不强制改变目标。想验证哪些对象，仍需写进任务描述和目标。

### 5.2 搜索和筛选资产

资产页面按类型查看，搜索框支持 DSL 表达式。例如：

```text
domain=lab.test AND status_code>=400
```

这是查询已入库数据，不会因为搜索而发起扫描。字段和操作符以搜索框提示为准；`=` 的包含匹配与 `==` 的精确匹配应按字段说明选择。复杂表达式先从一个条件开始，确认结果再追加。

删除企业时，认真看确认框是否包含其资产的删除选项。若只是暂时不想在某个任务中处理它，应优先移出该任务，而不是删除共享资产。

### 5.3 从 ScopeSentry 同步

1. 进入「资产同步 → ScopeSentry」。
2. 填写 **MCP 地址** 和 API Key；这里要的是对应 MCP 服务地址，不能用管理网页地址代替。
3. 保存数据源配置；修改时 API Key 留空表示保留原值。
4. 选择项目维度或任务维度，勾选要同步的来源。
5. 选择要同步的资产类型，再点击「同步选中」。
6. 看入库数量，到「资产」中核对类型、内容与归属。

同步是导入已有资产，不等于已经创建了 ARTEX 任务或执行了测试。数据源连不上时，分别核对服务地址、认证头、网络连通与启用状态。

## 6. 审核发现、归并和复测

### 6.1 先审核证据，再改处置状态

打开「发现」，按任务、严重程度、状态、类型等筛选，点击记录看详情。严重程度包括严重、高危、中危、低危；处置状态包括待处理、处理中、已确认、已处理、已修复、误报、忽略、重复、风险接受。

**评级描述影响大小，状态描述处理进度，两者互不替代。** 手动改成「已修复」只是修改记录，不会自动发起复测；标成「重复」也不等于自动创建漏洞文件夹。

建议依次核对：

1. 对象、接口或文件是否正确，记录属于哪个任务。
2. 事实和复现条件是否明确，报告有没有超出证据的推断。
3. 是否有可核对的命令输出、请求/响应或其他证据。
4. 是否需要修改名称、评级或处置状态。
5. 是否需要归并、补充证据或复测。

### 6.2 同一漏洞为什么会出现文件夹

「发现」默认按漏洞展示。确认同一任务内的多条原始上报来自同一实际缺陷后，会形成可展开的漏洞文件夹，提供统一报告。

点击箭头展开原始上报；点击文件夹标题查看统一报告、成员和归并历史。仅漏洞名称或类型相同，不足以判定同一根因。证据不足时可能显示待人工确认的建议，需要你选择是否确认归并。

历史数据不会自动全量整理。要处理旧记录：展开并选择原始记录，点击「整理所选」。它按任务排队，由 Reporter 读取既有材料并判断；需要可用模型，会产生 Token 用量。历史整理不重新探测目标，也不会替你补写原始报告或补绑证据。

关键边界：

- 归并保留原始上报、评级、状态、报告和证据。
- 移出成员不会删除原始漏洞；成员不足两条时文件夹解散并保留历史。
- 被否决或人工移出的关系不会被 Agent 自动再次归并。
- 成员、报告或证据变化后，统一报告可能变为「待更新」，可在详情重新生成。
- 文件夹的等级数量按原始记录统计；独立漏洞数按文件夹去重，两者不一定相加一致。

### 6.3 手动复测

入口包括漏洞列表行的「复测」、漏洞详情的「漏洞复测」，以及任务详情的「复测」页签。

1. 选择具体漏洞，填写可选的修复版本、测试条件或限制。
2. 发起复测，页面会显示「复测中」。
3. 需要了解过程时，进入对应的独立复测 Agent 会话。
4. 结束后看结论和证据：**仍可复现 / 已修复 / 无法确认**。

成功完成且结论为「已修复」时，系统自动把处置状态改为「已修复」。失败、停止、执行中或其他结论不会自动认定修复。原始报告和证据保留，同一漏洞已有运行中的复测时复用该会话。

复测不要求重启整个原任务，但会执行验证并使用模型。当前复测历史可在漏洞详情与会话中查看，**尚未纳入漏洞报告导出或任务归档包，也不会自动关联流量包**。交付时需要复测过程，应单独保存相关结论和证据。

## 7. 把流量变成可交付证据

### 7.1 先有录制，才可能关联

在「系统配置」开启「流量捕获」后，支持代理的 Agent HTTP 操作可进入记录代理。没有经过该代理的请求、非 HTTP 工具通信、开启前的请求，不能靠后续关联补出来。

「Agent 自动绑定流量」是另一个开关：默认关闭；开启后报告 Agent 会核对已有请求/响应，再关联到发现并写报告。它不会自动开启流量捕获。TCP 类问题或没有对应数据包时，仍可用其他真实证据保存发现。

### 7.2 从漏洞详情绑定

1. 打开目标漏洞详情的「关联流量」。
2. 在选择器里搜索并查看候选请求，核对实际方法、URL、参数、响应和上下文。
3. 勾选需要的记录，支持跨页多选，确认绑定。
4. 为每条证据选择用途、填写说明，并按阅读顺序排列。

| 用途 | 适用内容 |
| --- | --- |
| 正常对照（baseline） | 正常条件下的请求和响应 |
| 漏洞证明（proof） | 直接支持该漏洞结论的请求和响应 |
| 补充验证（verification） | 对结论的进一步验证 |
| 辅助证据（supporting） | 其他有帮助的上下文，也是默认用途 |

推荐说明写成“这个请求证明了什么”，而不是只写“见附件”。域名或时间接近只能帮助找到候选，不能证明这条流量属于该漏洞。

### 7.3 从流量页绑定

在「流量」页筛选主机、方法、路径、状态码或正文等，点击记录看 Request / Response。勾选多条记录后，使用关联入口，选择一个已有漏洞提交。

绑定后的内容保存为独立证据快照。普通流量清理不会删除已经绑定的证据正文，但并不因此可以省略备份。证据缺失或校验不通过时，导出可能整体失败，应恢复完整文件后重试。

修改用途、说明、排序或解除绑定后，已有报告可能提示待更新；应按最新证据重新生成并核对报告。继承任务中的证据只读，要调整请进入来源任务。

<a id="export"></a>

## 8. 导出报告

### 8.1 任务汇总

任务详情「报告」页展示汇总 Markdown，可点击「复制」。这个入口和「发现」页的批量文件导出不同，不要把任务汇总当成已下载完整流量附件。

### 8.2 批量导出发现

1. 在「发现」页先筛选任务、状态或评级，或勾选需要的记录。
2. 点击「导出」。
3. 确认范围：**当前筛选结果 / 全部 / 勾选项**。跨页选择可能保留，注意选中数量。
4. 选择格式并下载。

| 格式 | 适合用途 |
| --- | --- |
| Markdown 汇总报告 | 一份文档连续阅读 |
| Markdown 分文件 ZIP | 分别保存漏洞报告，并交付已绑定的请求、响应及原始正文附件 |
| CSV | 表格统计、分派和整理 |
| JSON | 保留结构化字段，供程序进一步处理 |

有漏洞文件夹时，默认导出每组统一报告及未归并记录；需要逐条审核可勾选「包含原始子报告」。统一报告未生成或过期时，导出会说明情况并附原始材料，应先检查内容是否满足交付要求。

ZIP 中的证据目录按漏洞和绑定编号组织，包含 `manifest.json`、`request.http`、`response.http`、`request.bin`、`response.bin`。CSV / JSON 不等于完整正文证据包。下载后解压并打开一份报告，确认相对链接和附件可读，再交付给别人。

## 9. 计划任务：按时间窗口工作

「计划任务」控制已有任务何时开始、暂停和恢复，也可在新建任务时附加计划。它不是每次到点就复制一条全新任务。

1. 新建计划并设置名称。
2. 选择「按周」或「指定日期」。
3. 选择北京时间或系统时区；系统时区是后端运行环境的时区，不一定等于浏览器时区。
4. 填开始时间和可选结束时间，绑定需要控制的任务。
5. 确认是否勾选「创建后立即启动，不等待第一个窗口」。
6. 保存后检查计划状态和运行时间线。

结束时间留空表示持续运行；结束时间早于开始时间表示跨午夜窗口。一次性计划还可填写截止日期。窗口结束会暂停任务，下一个有效窗口继续；已终态任务不能理解为会自动重新扫描。

例如，每周六 18:00–20:00 只安排一个本地练习任务：选按周、周六、北京时间、开始 18:00、结束 20:00，并绑定该任务。保存后先核对下一次窗口；如果当前不在窗口，等待是正常行为。

## 10. 工作空间与诊断记录

### 工作空间

「工作空间」浏览的是服务器文件，不是你电脑的任意目录。可查看、上传、下载和编辑允许访问的工作文件，编辑后记得保存。任务文件一般在 `data/tasks/` 下，独立对话文件在 `data/sessions/` 下。

不要在 Agent 正使用文件时随意重命名或删除。要保留一份分析材料，先下载或备份；仅在网页中打开过不代表保存到自己电脑。

### 工具执行

遇到“工具执行失败”，先到「工具执行」找对应时间和任务，展开输入与输出。常见原因包括命令不存在、路径在宿主机而非容器内、文件权限、目标不可达或审批拒绝。不要仅凭 Agent 的一句总结判断执行成功。

### LLM 录制

「LLM 录制」记录发给模型的请求和模型响应，开关默认关闭。需要分析格式不兼容、空响应、Token 用量或上下文问题时再开启，并用一个小请求复现。开关对后续调用生效，不能补录过去的调用。

这些记录可能包含提示词、工具结果和任务材料，分享前先脱敏；关闭开关并不会清空已经录制的数据。删除录制也不会退还已产生的模型用量。

### 后端日志

「日志」适合看当前服务运行错误。程序无法启动或网页根本打不开时，使用容器日志或启动终端输出；页面日志不能代替外部持久化日志文件。

## 11. 归档和删除

不活跃但仍需保留的任务，优先归档。当前任务列表和任务详情均提供归档入口。

1. 先暂停运行中或排队任务，或者选择已结束的任务。
2. 如果提示被其他未归档任务继承，先处理依赖它的任务。
3. 确认归档，等待状态完成；归档是后台作业，不是点完立即结束。
4. 到「任务 → 已归档」查看进度、错误和大小；需要继续查看时还原。

归档会将图谱、关联记录、工作文件、LLM 历史以及可清理的独占资产和流量打包到本机冷存储；共享数据按关联关系保留。归档文件仍在同一台服务器，**归档不是异机备份**，也不包含所有全局配置。

还原后检查任务状态、范围、附件与模型配置，再决定是否恢复执行。遇到失败可查看原因并重试，不要直接手工删归档目录。当前复测历史的归档限制见前文复测说明。

任务删除对话框里的附加清理项决定是否同时删除某些关联数据。永久删除归档不可恢复。若目的只是腾出页面空间，先用分类、筛选或归档；真正清理前完成[完整备份](部署维护与排错.md#backup)。
